# Starter code review

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses the punch timestamp's date/time zone when anchoring a shift and does not handle overnight shift dates. | A 09:40 IST punch can be judged against a UTC/local 09:30; an overnight punch before 06:00 anchors to the wrong day. | Convert the instant to IST and use the attendance-day shift anchor. |
| 2 | `compute_late_minutes` | Comparing floored minutes to 10 misses the strict 10-minute boundary; 09:40:01 is already late by the rule. | For a 09:30 shift, 09:40:01 incorrectly returns 0. | Compare elapsed whole seconds to 600, then floor total elapsed minutes. |
| 3 | `compute_work_hours` | Python `round` uses binary floats and ties-to-even rather than decimal half-up. | A value exactly halfway between hundredths can round down unexpectedly. | Calculate from whole seconds with `Decimal` and `ROUND_HALF_UP`. |
| 4 | `compute_overtime` | Anchors shift end to a naive date and ignores overnight shifts; it also lacks the 30-minute minimum. | A 22:00-06:00 shift can get nonsensical overtime; a 10-minute overrun should be zero. | Build the end instant in IST on the correct day and apply the 30-minute threshold. |
| 5 | `health` | Always reports ready without checking MongoDB. | Stop MongoDB and `/health` still returns 200. | Ping MongoDB and return 503 on a database error. |
| 6 | `create_employee` | Check-then-insert is race-prone; it trusts client input without schema validation; creation time is naive; and returned `created_at` is not epoch milliseconds. | Parallel creates can both pass the check; malformed codes/dates/shifts pass; the timestamp response violates the contract. | Validate with Pydantic, enforce a unique index, handle duplicate-key errors, store UTC and serialize epoch milliseconds. |
| 7 | `list_employees` | `skip` starts at `page * page_size`, total ignores the department filter, and there is no deterministic sort or pagination bounds. | Page 1 skips the first 20; filtered total is incorrect. | Use `(page - 1) * page_size`, filtered counts, sorting, and bounded query parameters. |
| 8 | `punch_in` | Unknown employees cause a key error; timestamps use host-local time and seconds instead of epoch milliseconds/IST; status and timestamp are unchecked; date assignment is wrong near midnight; check-then-insert races; response leaks an `id`. | Unknown code produces 500, UTC-dependent dates differ across machines, and concurrent duplicate punches may both succeed. | Validate inputs, use UTC epoch conversion and IST attendance-day logic, enforce the unique natural key, and return only contract fields. |
| 9 | `list_attendance` | Reads and sorts the entire collection in Python, omits the contract sort tie-break, does not validate dates/ranges, and returns Mongo datetimes plus `_id`/an internal id shape. | Large datasets are slow; malformed/reversed dates are accepted; response instants are not epoch milliseconds. | Filter/count/page/sort in MongoDB and serialize only API fields. |
| 10 | Startup / database setup | No indexes are created, so uniqueness is not guaranteed and list/analytics queries can scan collections. | Duplicate records can be written and explain plans show collection scans. | Create idempotent unique and query-supporting indexes at application startup. |
| 11 | Missing contract endpoints | Punch-out, correction, analytics, and explain behavior are absent. | The listed routes return 404. | Implement each route, including atomic updates, append-only correction history, aggregation pipelines, and explain output. |

**Checked and not a defect:** defaulting omitted `status` to `PRESENT`, and initializing new records with null punch-out/work-hours and zero overtime, are consistent with the contract. Using `emp_code` as the employee key is also intentional; MongoDB `_id` is not the business identifier.
